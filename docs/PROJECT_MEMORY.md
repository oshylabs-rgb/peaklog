# PeakLog — project memory

Last updated: 20 Oct 2026 (legs 3x, Fri/Sun rest, layouts). Single-file static PWA (`index.html`), localStorage key `peaklog.v1`, no backend. Deploys from GitHub to Vercel (see `DEPLOY.md`). Never store secrets here.

## Current objective
Rotating training blocks that suit Arnold's body, deadlifts and squats properly programmed, loaded posture work inside the lift days, and a weekly "growing or slipping?" snapshot — without losing any logged data.

## PRD — rotation + snapshot (19 Oct 2026)
- **Problem.** The programme was one static week. No conventional deadlift, RDL as the only hinge, squats thin on the legacy log, posture work not loaded, and no single answer to "am I going backward?".
- **User.** One lifter, 37, ~78 kg / ~14% body fat, desk job, 45-minute lift cap, Mon/Wed/Fri/Sat lifts + rower Tue + treadmill Z2 Thu + Sunday rest.
- **Success.** Blocks rotate by date with no manual step; every lift day fits 45 min; every block has squat + deadlift + posture; weights re-set correctly at block changes; all prior data survives; the snapshot gives a verdict and the numbers behind it.
- **Scope.** Rotation engine, 3 blocks x 4 lift days, exercise library additions, block-aware prescriptions, Workout tab follows the rotation, snapshot card (Today + Review), migration + backup. Out of scope: nutrition phase changes, cardio rotation, notifications.
- **Constraints.** Local-first, no build step, 45-minute hard cap, existing session screen/progression semantics unchanged for pre-rotation dates.
- **Risks.** Wrong starting weights on new lifts (mitigated: seeded from RDL / squat / deadlift history, else the InBody estimate flagged "calibration"); rep-range change misreading progress (mitigated: e1RM conversion and e1RM-based snapshot); false "Slipping" from deloads or pre-logging weeks (mitigated and tested).

## Decisions
- **Rotation = Build (6–10) → Strength (3–6) → Volume (8–15), 6 weeks each (5 loading + deload), repeating.** Anchors are an append-only list so "start next block now" never relabels past weeks.
- **Squat and deadlift anchors stay in every block**; variations rotate (hack/front/Bulgarian, conventional/trap-bar). Stiff-legged deadlift replaces RDL on Lower A. RDL stays in the library as `retired` so history resolves, and SLDL seeds from logged RDL weights x 0.9.
- **"Posture workouts" interpretation.** The app contained no posture day or home routine (only a "mobility / rest" label and a cardio form cue). Read as: make posture work weight-based and keep it inside the existing gym days. Built as compound+posture supersets (face pull, CS row, rows, rear delt fly, Y-raise, hip thrust, deadlifts, farmer's carry), 29–31 sets/week per block. If a separate home routine was meant, say so and it can be added as an optional list.
- **One plan, two logging screens.** `TEMPLATE` (old static PPL) was removed; `tplFor(date)` builds the Workout-tab day from the rotation, so the Today session card and the Workout tab can't disagree. Days already logged are stored in full and untouched.
- **Snapshot judged on strength first (best e1RM vs median of last 3 non-deload weeks: up >= +1%, down <= -2%), consistency second.** Body weight/fat shown for context, not scored; the existing weight-trend card (`projection()`, gain mode) already owns bulk judgement.
- **Six lifting days, Sunday rest (follow-up, 20 Oct 2026).** Arnold saw Tue/Thu/Sun with no exercises and asked for a plan that gives exercises, weight and reps from his InBody on every day. Tue (Pull A) and Thu (Push B) became lifting days, so the week is push / pull / legs x2 (the structure he ran before the Aug module), Sunday is the one rest day. Cardio (rower intervals, incline Z2) is now optional on a bulk, kept as buttons on the Today card and an optional log on the Workout tab; nothing was deleted. Snapshot consistency target is 6 lifting sessions in the rotation (4 lifts + 2 cardio for weeks before it). Rule enforced by test: an exercise on two days of one block uses the same rep range on both, otherwise double progression would reset every session.
- **Every loaded weight is InBody-driven.** The 20 accessories that used fixed start weights now use `lbmMult`, calibrated to reproduce today's numbers exactly at the current scan (78.1 kg, 13.9%, lean mass 67.2 kg) and to scale with any new scan. The InBody basis is stated once on the Today card and on Plan > Rotation. The scan on file is 1 Aug 2026; a newer scan entered on the Data tab rescales everything.
- **Fast logging (follow-up, 20 Oct 2026).** Arnold asked for logging that is easy: pressing all the sets and reps quickly. Session screen rebuilt as exercise cards (one open at a time, auto-advance) with tap-a-set, tap-the-reps, All sets, undo, skip-rest and log-whole-session-as-prescribed; Workout tab got rep buttons + fill-the-rest. `render()` now keeps scroll position when the screen is unchanged (it jumped to the top after every tap, also on the supplements ticks). Guard against false data: the "All sets" and whole-session buttons state the reps they will log, ask for confirmation at session level, and everything is undoable; suggested reps never default above what was last done (first time = bottom of the range, so a blind tap can't fake a progression).
- **Legs three times, rest Fri/Sun, layout changes after three weeks (follow-up, 20 Oct 2026).** Arnold: the InBody shows lower body behind upper body, so legs at least 3x a week; rest days ideally only Friday or Sunday, sometimes one sometimes the other; the weeks' rotation should change after a few weeks. Built as: Tue/Thu/Sat are always leg days (Legs 1 squat / Legs 2 deadlift / Legs 3 glutes + single-leg), upper body is three sessions (Push, Pull, Upper = shoulders + arms) so it dropped from four days to three; one rest day a week, Friday or Sunday, alternating from the first rotation week, per-week override incl. "both" (five-day week, drops the Upper day). "Weeks rotations change after a few weeks" was read as the weekly layout: layout A for weeks 1-3 of each block, layout B for weeks 4-6 (the three leg sessions swap days, Push and Pull swap days); exercise selection already changes every 6-week block. If a different cadence or a different meaning was intended, `WM_HALF_WEEKS` and `WM_LAYOUTS` are the two knobs. Plan ids are unchanged so history resolves (upperA=Push, upperB=Pull, pushB=Upper, lowerA/lowerB/legsC=Legs 1/2/3; `pullA` retired, kept only for past sessions). Leg share of weekly weights sets went from ~30% (36 of 120) to ~43% (45 of 105 in Build); the number shown on Plan > Rotation is computed, not typed.
- **UI cleanup (26 Oct 2026).** Arnold: the routines felt like a patchwork; outcome is bigger muscles and eating more; programme left as is, UI simplified. Today: "Bulk" card (weight, last body fat, trend vs the lean-gain band, one-tap weigh-in) replaces the countdown to the expired August goal; phase card and the duplicate "Log workout" card removed; session card is a short list with one Start button; snapshot folded to one line. Workout tab is now history (sessions from the session screen, read-only) with the manual log folded away. Plan: lists folded, roadmap one line per block, squat/deadlift card removed. Snapshot treats nothing as "due" before the rotation's first week, which removes the false "Slipping" for pre-update weeks. Page length: Today 33% shorter, Workout 90%, Plan 55%. No programme or data change.
- **The bulk is intentional and off-limits (confirmed by Arnold, 19 Oct 2026).** He is bulking from October 2026 for at least 5 months. The August goal (12 Aug 2026) and the Phase 1/2 nutrition config (ended 3 Sep) are out of date on purpose. Do NOT refresh them, change targets or macros, add a phase, reset `appliedPhase`, or raise them as stale/blocked. With no active phase the app runs in its gain / lean-bulk mode. The rotation and snapshot never write to `targets`, `profile.goalDate` or the phase config (the planRev-8 migration is tested to leave them alone).
- **Frozen pre-rotation week.** `WM_DAYS` lift days are kept only for dates before the rotation began, so old sessions render as they were done.

## Known limitations / next actions
- Session time is modelled (35 s a set, prescribed rests); real sessions may run longer. The cap still auto-flags unlogged sets as skipped.
- Starting loads for brand-new lifts are estimates until the first session is logged.
- Trap-bar deadlift assumes a trap bar (or sumo as the substitute).
